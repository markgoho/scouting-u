# Default to uni-theme-first for shared UI shells; local stays the exception

**Status**: accepted

Supersedes the default set by [ADR 0005](0005-local-first-templates-and-css-against-uni-theme.md). ADR 0005's default was: build local in whichever site needs it first, converge into `uni-theme` only on a named trigger. In practice that default flipped every time it was tested — [ADR 0006](0006-layout-mechanics-from-uni-theme-content-styling-stays-local.md) pulled generic layout mechanics into `uni-theme`, and [ADR 0007](0007-adopt-unithemes-timeline-and-req-list-primitives.md) pulled the timeline/req-list card shell in too, both because building locally first just meant re-deriving a shape `uni-theme` should have owned from the start. The pattern is repeating again with the rank landing page (#44): it needs a hero/preview/facts/resources shell whose MBU counterpart (`badge-landing.html`, `merit-badge-landing.css`) already exists, badge-named, in `uni-theme`.

Going forward, when a page-level UI shell already exists for one sibling site (mbu or scouting-u) and the other site needs the same shape, genericize it in `uni-theme` first — rename the site-specific classes (`.badge-preview` → a domain-neutral name, etc.) and land that in `uni-theme` — then update both sites' HTML to the new class names, rather than reusing the site-specific classes as-is or duplicating the CSS locally. Content genuinely shaped by one domain's own data (rank's leaf/group requirement-tree structure, mbu's guide/`subrequirement_mode` fields) still stays local, per ADR 0005/0006's still-valid carve-out for content-bound styling — the default flips only for structural/presentational shells that already have a working twin in the other site.

This doesn't retroactively require migrating UI that's already reusing site-specific classes as-is (e.g. `badge-identity`/`req-card` reuse from #18) — it sets the default for new work. It also reopens ADR 0007's known gap: mbu's own live templates were never migrated to `.timeline`/`.req-list` after that primitive landed. Close that opportunistically when next touching mbu's requirements page, rather than leaving `uni-theme` with a primitive only one sibling actually uses.
